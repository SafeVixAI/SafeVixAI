## Code of Conduct

SafeVixAI follows the [Contributor Covenant v2.1](../CODE_OF_CONDUCT.md). All community spaces — GitHub Issues, Discussions, pull requests — are governed by this code.

**Reporting violations:** `safevixai@googlegroups.com` — all reports are kept confidential.

---

## Communication Channels

| Channel | Purpose | SLA |
|---------|---------|-----|
| [GitHub Issues](https://github.com/SafeVixAI/SafeVixAI/issues) | Bug reports, feature requests | 1-2 business days |
| [GitHub Discussions](https://github.com/SafeVixAI/SafeVixAI/discussions) | Q&A, ideas, show-and-tell | 1-3 business days |
| Mailing List | `safevixai@googlegroups.com` | 48 hours |
| Security Reports | See [SECURITY.md](../SECURITY.md) | 48-hour acknowledgement |

### When to Use What

- **Bug** → GitHub Issue with bug report template
- **Question** → Search Issues, then open a Discussion
- **Feature proposal** → Discussion for design feedback
- **Security** → Email `security@safevixai.gov.in` — never public
- **General feedback** → Discussions or mailing list

## RFC Process

Significant changes follow a Request for Comments (RFC) process:

1. **Pre-RFC** — Discussion thread describing the problem and solution
2. **RFC** — Formal document in `docs/rfcs/` as a PR
3. **Comment Period** — Minimum 7-day review
4. **Decision** — Consensus-based (Accepted, Rejected, Requires Revision)
5. **Implementation** — Tracked as GitHub Issue with `rfc-accepted` label

Small changes (bug fixes, minor UI, docs) skip the RFC process.

## Contribution Ladder

```
First-Time Contributor → Contributor → Core Contributor → Security Team → Project Lead
```

| Role | Requirements |
|------|-------------|
| First-Time Contributor | One PR merged |
| Contributor | Multiple PRs, active in Discussions |
| Core Contributor | 5+ merged PRs, 3+ months activity, nominated |
| Security Team | Sub-group of Core Contributors |
| Project Lead | Founding team (currently) |

See [GOVERNANCE.md](../GOVERNANCE.md) for detailed criteria.

## Mentorship

- **Good First Issues** — Tagged with designated mentors
- **Buddy System** — Core Contributor assigned as your PR buddy
- **Office Hours** — Weekly (posted in Discussions)
- **Pair Programming** — Available for complex changes

To be mentored: comment on a `good first issue` or `help wanted` issue.

---

## Conflict Resolution

1. **Direct communication** — Reach out privately
2. **Mediation** — Ask a Core Contributor to mediate
3. **Escalation** — Project Lead makes final binding decision

All conflicts handled under the [Code of Conduct](../CODE_OF_CONDUCT.md). Retaliation is not tolerated.
